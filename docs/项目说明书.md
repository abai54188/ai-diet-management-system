# AI 智能饮食管理系统 — 项目说明书

## 1. 项目概述

### 1.1 项目背景

随着大众健康意识的提升，越来越多的人需要一套能「记录饮食、分析营养、科学管理体重」的工具。传统营养类 App 往往只做简单的食物热量查询，缺少个性化分析与智能建议。本项目将 **AI 大模型** 与 **本地营养数据库** 结合，在保证营养数据精确（由本地库 + 打卡记录计算）的前提下，用大模型生成自然语言建议、推荐食谱、识别食材，从而降低用户的使用门槛。

### 1.2 项目定位

一款面向个人用户的 **智能饮食与体重健康管理系统**，提供从「记录 → 分析 → 建议 → 管理」的完整闭环。

### 1.3 核心设计原则

- **数据准确性**：热量/蛋白质/碳水/脂肪等营养值一律由本地营养库与打卡记录精确计算，大模型**不虚构**营养数据，仅负责生成自然语言建议。
- **低部署门槛**：数据库采用 SQLite 单文件，免装 MySQL；前后端一体化打包为单个 jar，双击脚本即可运行。
- **安全可控**：JWT 鉴权 + BCrypt 密码加密 + 敏感信息（API 密钥）通过环境变量注入，不入库。

## 2. 系统功能模块

系统共划分为 **8 大功能域**：

### 2.1 用户与认证
- 注册、登录、JWT 令牌鉴权
- 角色体系：`USER`（普通用户）/ `ADMIN`（管理员）
- 个人资料维护

### 2.2 健康档案
- 维护身高、体重、目标体重、年龄、性别、活动量、健康目标、忌口/过敏源
- 为营养建议与食谱生成提供用户上下文

### 2.3 食材与营养
- 本地营养库 1200+ 条食材数据
- 食材分页检索、分类、别名（alias）查询
- 多选食材构建饮食方案，实时汇总热量与三大营养素

### 2.4 AI 能力
- **拍照识菜**：拍摄/上传食物照片，视觉大模型（如 `qwen-vl-plus`）识别菜品、估算各食材重量，本地营养库精确计算热量与营养；重量可手动调整并按比例重算
- **AI 食谱生成**：基于已选食材 + 健康档案生成多套菜单与做法
- **营养助手**：大模型对话式营养咨询
- **饮食建议**：综合健康档案 + 当日摄入 + 数据对比，生成个性化建议

### 2.5 饮食与体重管理
- 饮食打卡：记录每餐食物（支持 AI 整道菜打卡）
- 体重管理：记录体重、趋势曲线、BMI 计算
- 健康分析：营养摄入与体重变化可视化

### 2.6 社区
- 发布动态、点赞、评论、关注
- 食谱收藏与评分
- 敏感词过滤、内容举报

### 2.7 数据看板
- 个人健康数据概览统计

### 2.8 后台管理（ADMIN）
- 用户管理、内容管理、食材库管理、数据统计

## 3. 系统架构

```
┌─────────────────────────────────────────────┐
│                 浏览器 / 客户端               │
│        Vue 3 + Element Plus (SPA)           │
└──────────────────┬──────────────────────────┘
                   │ HTTP (JSON, /api/**)
                   │ HTTPS / 一体化同源
┌──────────────────▼──────────────────────────┐
│           Spring Boot 3.2 (后端服务)          │
│  ┌────────────┐  ┌──────────────────────┐   │
│  │ JWT 拦截器  │  │ 静态资源托管 + SPA 兜底 │   │
│  └────────────┘  └──────────────────────┘   │
│  Controller → Service → Mapper (MyBatis-Plus)│
│  ┌──────────────────────────────────────┐   │
│  │  AiClient (OpenAI 兼容协议, 大模型调用) │   │
│  └──────────────────────────────────────┘   │
└──────────────┬───────────────┬───────────────┘
               │               │
      ┌────────▼───────┐   ┌───▼───────────────┐
      │  SQLite 数据库  │   │  大模型(阿里云百炼) │
      │  (diet.db)     │   │  (DashScope)      │
      └────────────────┘   └───────────────────┘
```

### 3.1 分模块说明

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 表现层 | Vue 3 + Vite + Element Plus + ECharts | 页面渲染、交互、可视化 |
| 通信层 | Axios（`baseURL=/api`） | 统一请求封装、令牌注入、错误拦截 |
| 控制层 | Spring MVC Controller | 接收请求、参数校验、返回统一 `Result` |
| 业务层 | Spring Service | 核心业务逻辑、事务管理 |
| 数据层 | MyBatis-Plus Mapper | 数据库 CRUD、分页 |
| 存储层 | SQLite (sqlite-jdbc) | 单文件关系型存储 |
| 安全层 | jjwt + BCrypt | 令牌认证 + 密码加密 |
| AI 层 | 原生 HttpURLConnection + OpenAI 协议 | 识菜、食谱、助手、建议 |

## 4. 数据库设计

共 **15 张表**（见后端 `resources/schema.sql`，均使用 `CREATE TABLE IF NOT EXISTS` 幂等定义）。

| 表名 | 说明 |
| --- | --- |
| `sys_user` | 用户表（含健康档案字段：身高/体重/目标体重/年龄/性别/活动量/健康目标/忌口） |
| `food_nutrition` | 食材营养库（热量/蛋白质/碳水/脂肪/维生素/矿物质等） |
| `user_food_collect` | 用户已选食材（自定义重量） |
| `diet_record` | 饮食打卡记录 |
| `health_profile` | 健康档案 |
| `recipe` | 食谱 |
| `weight_record` | 体重记录 |
| `ai_chat_message` | AI 对话消息记录 |
| `community_post` | 社区动态 |
| `post_comment` | 动态评论 |
| `post_like` | 动态点赞 |
| `user_follow` | 用户关注 |
| `recipe_collect` | 食谱收藏 |
| `recipe_rating` | 食谱评分 |
| `content_report` | 内容举报 |

**关键设计点：**
- `diet_record.food_id` 允许为空，支持「AI 整道菜打卡」场景（无具体食材 ID）。
- 逻辑删除：核心表含 `deleted` 字段，`0` 未删除 / `1` 已删除。
- `food_nutrition.alias` 支持食材别名检索。
- 时间字段默认 `datetime('now','localtime')`，避免创建时间为空。

## 5. 接口设计

后端统一返回结构 `Result<T>`：`{ code, message, data }`，其中 `code=200` 表示成功，`401` 表示未登录/令牌失效。

主要接口分组（前缀 `/api`）：

| 分组 | 路径示例 | 说明 |
| --- | --- | --- |
| 认证 | `/api/auth/login`、`/api/auth/register` | 登录/注册 |
| 用户 | `/api/user/**` | 个人信息、健康档案 |
| 食材 | `/api/food/**` | 营养库查询 |
| 打卡 | `/api/diet-record/**` | 饮食打卡 |
| 食谱 | `/api/recipe/**` | 食谱查询/生成 |
| AI | `/api/ai/**` | 识菜/食谱/助手/建议 |
| 体重 | `/api/weight/**` | 体重记录与趋势 |
| 社区 | `/api/community/**` | 动态/评论/点赞/关注 |
| 统计 | `/api/stats/**` | 数据看板 |
| 后台 | `/api/admin/**` | 用户/内容/食材/统计管理 |

> 除 `/api/auth/login`、`/api/auth/register` 外，其余接口均需在请求头携带 `Authorization: Bearer <token>`。

## 6. 技术要点

### 6.1 前后端一体化部署
- Vite 构建产物输出至 `backend/src/main/resources/static`；
- Spring Boot 通过 `WebMvcConfig` 托管静态资源，并对 Vue Router history 模式做 SPA 兜底（找不到文件时回退 `index.html`），解决深层路由刷新 404 问题。

### 6.2 SQLite 初始化
- `spring.sql.init.mode: always` + `schema.sql` / `data.sql` 幂等脚本，首次启动自动建表并导入种子数据。

### 6.3 AI 调用健壮性
- 采用原生 `HttpURLConnection`，显式设置 `Content-Type: application/json;charset=UTF-8` 与 `Accept` 头、固定长度流式模式，按字节流读取原始响应，规避 DashScope 因分块/请求头差异返回 `application/octet-stream` 被拒的问题。
- 读超时放宽至 180s，适配生成多套菜单耗时场景。

### 6.4 营养数据边界
- 营养数值由本地库 + 打卡记录计算，大模型仅产出自然语言，保证准确性。
